# Scope audit: one row per permission (79)

Written 14 Nov 2026. Ground truth for the list: the developer portal draft read after reload (79 selected: 7 required, 72 optional; `locations/tasks.write` removed). Code (`GHL_SCOPES`), `src/lib/scope-groups.ts`, `docs/SCOPES.md` and `docs/SCOPE_COVERAGE.md` match it exactly (checked by a script and by `scopes.test.ts`).

How each row was made
- **Endpoint(s) the docs tie to the scope**: from the official OpenAPI files of the platform's public documentation repository (the `security` block of every operation), and, for scopes the older files do not show, from the platform's own operation catalogue (the `requiredScopes` of each operation). Rows say "none found" when neither source ties an endpoint to the scope.
- **Screen and code**: the screen is the menu path from `docs/SCOPE_COVERAGE.md`; the files are the SubSync source files that contain that exact endpoint path (path match, any method). "no SubSync code calls it" means no file contains a matching path.
- **Docs say the call needs this scope**: yes only when a path SubSync calls is documented as guarded by this scope.
- **Live-tested**: yes only for the nine permissions that answered from the real accounts on 30 to 31 Oct and 13 Nov 2026. Everything else was tested with a recorded fake of the platform, never a real account.
- A second check ran the other way: every API path SubSync calls was matched to the documented scopes of that path. Paths whose scope is not in the portal list: `/medias/files` (needs `medias.readonly`), `/saas/saas-locations` and `/saas/saas-plan` (need `saas/company.read`, which this app cannot be given; the screens say Needs permission or Not available), `/wallet/*` (no documented scope). Other paths are newer than the older files and were confirmed in the catalogue.
