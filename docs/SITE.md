# The public site (home, support, trust, privacy, terms, install page)

Static pages, no database. Server components; the only client JavaScript is the video player, the support search and the 5-second redirect on the install page.

## Structure
| Route | File | Notes |
|---|---|---|
| `/` | `src/app/page.tsx` | Hero, video, pain cards, ten page sections with real screenshots, how it works, pricing, trust, FAQ. Install is the main button (`INSTALL_HREF`, the existing `/api/oauth/install` route). No audit or calculator calls to action. |
| `/support` | `src/app/support/page.tsx` | Search, quick start, A to Z index, video, contact. |
| `/support/<slug>` | `src/app/support/[slug]/page.tsx` | One page per entry of `DOC_PAGES` in `src/lib/site/docs.ts`. |
| `/support/glossary`, `/support/changelog` | own folders | Changelog reads `NEWS` in `src/lib/whats-new.ts` (live entries only). |
| `/trust` | `src/app/trust/page.tsx` | Short proof at the top, then the sections generated by `src/lib/trust.ts`. |
| `/privacy`, `/terms` | own folders | Plain-language documents. Lists come from code (`data-inventory.ts`, `scope-groups.ts`, `company.ts`, `trust.ts`). |
| `/installed`, `/installed/error` | `src/app/installed/` | Onboarding page after install (noindex). |
| `/api/open-crm` | `src/app/api/open-crm/route.ts` | The install page button goes here so the page never contains the CRM address; it redirects to the company's own domain. |
| `sitemap.xml`, `robots.txt`, `manifest.webmanifest` | `src/app/sitemap.ts`, `robots.ts`, `manifest.ts` | Routes come from `src/lib/site/routes.ts`. The app routes are disallowed. |

Design: `src/components/site/site.css` (scoped under `.site`, one accent taken from the logo, dark by default, light when the device asks, reduced motion respected). Shell: `src/components/site/shell.tsx`.

## One source for the app and the website
The in-app guides (`src/lib/guides.ts` plus `src/lib/concept-guides.ts`) are the text. `src/lib/site/docs.ts` builds each public page from the guides it lists (`guideIds`) and adds who it is for, steps, what is read and changed, numbers and questions. `src/lib/site/doc-map.ts` is the small guide-to-page map the app screens import ("Read the full guide" links). `src/lib/__tests__/site-docs.test.ts` fails when a guide has no page or the two maps differ.

### Add a feature page
1. Write the guide (4 to 8 plain bullets, `tryView`) in `src/lib/concept-guides.ts` (or `guides.ts` for a menu page).
2. Add a `DocPage` to `DOC_PAGES` in `docs.ts` with `guideIds`, and the guide id to `doc-map.ts`.
3. `npm test` (node tests) must pass. The sitemap and search index pick the page up by themselves.

## Swap the video (one command)
The site reads three fixed paths: `/video/subsync-tour-720.mp4`, `/video/subsync-tour-poster.jpg`, `/video/subsync-tour.en.vtt` (see `VIDEO` in `src/lib/site/config.ts`).
When v4 is finished:
```
SUBSYNC_VIDEO_OUT=<folder with subsync-preview.mp4 and the poster> node scripts/make-web-video.mjs --plan <path to the video tool's plan.json>
```
It encodes 720p (and a 1080p copy that is git-ignored; use `--no-1080` to skip it), rebuilds the poster and builds the captions from the plan (timings come from `plan.json` lines: `start`, `dur`, `chunks`; a trimmed copy of the v3 plan is kept in `scripts/video/captions-plan.json`). Commit the new 720p, poster and VTT. The 62 MB master is never committed. Update `VIDEO.durationIso` in `config.ts` if the length changes.

## Pictures and icons
`node scripts/make-site-assets.mjs` (needs the folder `assets/` with `brand/` and `listing/upload-ready/`; set `SUBSYNC_ASSETS` if it is elsewhere) writes the screenshots to `public/site` as webp (1600 and 800 wide), the logo files to `public/brand`, `public/icon-*.png`, `apple-touch-icon.png`, `src/app/favicon.ico` and `public/og.png`. `node scripts/make-install-stills.mjs` makes the arrow stills of SubSync's own menu used on the install page. The scripts' output is committed. Note: `*.mjs` is ignored by a local git exclude on King's machine, so use `git add -f` for new scripts.
The brief asked for the transparent cut-out `subsync-logo-main-transparent.png`; it was not in `assets/brand`, so `subsync-logo-main.png` (which has a transparent background) is used and trimmed.

## Wording rules (checked by tests)
No vendor name or logo anywhere (pages, metadata, alt text, file names, captions, sitemap, manifest), no "sub-account". Say "your CRM" and "client account". `src/lib/__tests__/banned-terms.test.ts` scans visible text; `site-docs.test.ts` scans sources, file names and, when `.next` exists, the built HTML.

## Install and pricing
- `/install` (`src/app/install/route.ts`, helper `src/lib/install-redirect.ts`) is the only address the pages use for installing. Order: `MARKETPLACE_LISTING_URL` (set it to the listing link shown in the developer portal; must be https) > the install URL the app already builds (`buildInstallUrl`, src/lib/ghl/scopes.ts: client id, redirect address, permissions) > `/support#install`. `/api/oauth/install` still works.
- `/pricing` and the pricing section of the home page read the price from `PRICING` in `src/lib/site/config.ts` (Growth, 14 days free, then $11.50 per client account per month; matches the comment in `src/lib/entitlements-core.ts` and docs/PERMISSIONS_AND_PRICING.md). `src/lib/site/pricing-calc.ts` does the calculator arithmetic; a test checks it against `PRICING`.
- OPEN QUESTION (white-label install address): the official marketplace docs (Authorization and App Review Guidelines, read 13 Nov 2026) do not state an install or listing address per white-label domain; they only say a white-label app must show no vendor branding during install. The only documented pattern in this repo's research is the branded install host (docs/features/S0.3.md), which `/install` already uses. So a visitor's own CRM domain is validated (`crm` query value, host only, no IP) but NOT used to build an address, and the "Where is your CRM?" field was not added. To unblock: King pastes the listing link from the portal into `MARKETPLACE_LISTING_URL`, or asks the platform which address a white-label agency's marketplace uses; then extend `installTarget`.
- After install the person lands on `/installed` and is sent back into their CRM through `/api/open-crm`, which uses the company's stored domain (the install callback signs it into the address; no token travels in the address).
