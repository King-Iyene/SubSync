# D1: Design polish, light and dark, and the buyer and UX review (Mode A)

Status: **BUILT, awaiting King's sign-off** (3 Nov 2026). Not marked passed. STOP here for King.

Goal (from `docs/ROADMAP_V2.md`, D1): a mature, consistent finish of the pilot pages on the approved D0 system. No new direction. Remove cards inside cards, vary the layouts, add restrained motion (count-up, skeleton loading, hover and focus states, all off under reduced motion), proper chart styling, fix contrast, verify light and dark on every pilot page, run the buyer and UX review in Mode A and fix every S0 and S1 that is a UI or copy issue.

Pilot pages covered: Today, Speed to lead, Appointments, Unanswered messages, Account audit, Clients, People, Settings, Getting started, What's new (and My day and the business view for the role check).

## 1. Five evaluation lines (principle 1)

- **(a) Decision and for whom.** King: is this mature enough to show a pilot agency. Every user: find the one thing to do on a screen without reading a paragraph.
- **(b) Data truly available.** No new data. Everything is the existing endpoints on the demo company, so every figure in the screenshots is a demo figure. Not tested on a real account in this stage.
- **(c) Does the CRM or a competitor do it.** Not a feature stage. It is the finish of what D0 approved.
- **(d) Simplest version.** Change the shared pieces (`Card`, `Stat`, `Table`, `Loading`, the toolbar) so every page improves at once, then fix the few pages that draw their own boxes. No new library, no new colour.
- **(e) Risk.** Shell and shared pieces touch every page. Mitigation: no data-testid or visible wording that a test asserts on was changed; the unit, component and browser suites were run (section 6); one test was adapted for the new loading state (DECISIONS).
