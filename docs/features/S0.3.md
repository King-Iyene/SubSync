# S0.3: White-label hygiene

Status: built and verified (31 Oct 2026). King said to keep going without waiting for PASS, so S0.3 is recorded as built and verified, and its five checks are below for review.

## Goal

Nothing a white-label customer sees reveals the platform behind SubSync, and every "Open in your CRM" link lands on their own domain.

## What the code did at the start of the stage (found by reading it)

1. `src/lib/links.ts` already built every CRM link from the agency's domain (the domain sent at sign-in, or the one typed in Settings, which wins). It was called `deepLinks`; the runbook asks for a `crmUrl(identity, path)` helper.
2. A line-based test already scanned for the platform's name (GoHighLevel, HighLevel, LeadConnector, GHL). It missed text split over several lines and it did not check "agency", "sub-account" or "location" at all.
3. 31 places that a person can read said "agency" (screens, errors, the sign-in refusal messages, the connected page, the AI connector description, the Help FAQ, the demo banner and the left menu label "Agency view").
4. No browser test opened screens as a white-label customer.

## Decisions

- **`crmUrl(source, path)`** in `src/lib/links.ts` is the only place a CRM address is made. `source` is a domain or anything carrying one (the signed-in identity's `whitelabelDomain`, or the saved settings' `appDomain`). Order: the domain typed in Settings, then the sign-in domain, then the default host only when neither exists. The path can never change the host. `deepLinks` is built on it.
- **Words:** "agency" becomes "company" (or "your team"), "Agency view" becomes "All client accounts", "location" becomes "account". The internal code values (`kind: "agency"`, database columns, JSON field names) stay; they are not text.
- **Exception, recorded:** the public pages that speak to agencies as their audience (home, privacy, terms, support) may say "agency". They may never name the platform or say "sub-account" or "location". The in-app screens, emails, errors, install pages and the share page have no exception.
- **Machine-only text** that must name the platform is allowed by two narrow patterns in the test: the webhook's signature header name (`x-ghl-signature`) and the browser's own `location.origin` in the one-line script that closes the connect popup.
- The CRM's own address path (`/v2/location/...`) contains the word "location". It appears only in a link's address, so the browser test removes addresses before it checks wording, and checks them separately for the platform's host names.

## Definitions

None added to `docs/METRICS.md` (no metric in this stage).

## Edge cases

- Text on several lines, inside template strings and inside page markup.
- Database queries, comments, imports and identifiers must not trigger the scan (they are not text).
- A domain that is not a plain host name, a path with spaces or a second host (`//evil.com`), a missing leading slash.
- A settings domain and a sign-in domain that both exist.
- Phone and email links on screens.
- A share link that does not exist.

## Acceptance criteria

1. `crmUrl` and `deepLinks` have unit tests for the white-label domain, the fallback, bad domains and bad paths.
2. A syntax-tree scan of every file that can reach a screen, email, message or error fails on the platform's name, its host names, "agency", "sub-account" or "location" in text, and passes on code, queries and comments.
3. A browser run with a fake white-label domain opens the 20 menu screens, the public pages, the install pages and an unknown share link, and finds none of the banned words, none of the platform's host names, and no link to the platform's default address. At least one Open link points at the fake domain.
4. The shared audit page built from real test data is checked for the same words in `scripts/check-tenancy.ts`.
5. `npm run verify` and `npm run e2e` green.

### King's 5 checks

1. **Words.** Open SubSync from a white-label account's menu. On Today, Accounts, Speed to lead, Appointments and Settings press Ctrl+F and search for: HighLevel, GHL, agency, sub-account, location. Expect no match (other than names you typed yourself).
2. **Your domain.** In Settings type your white-label login domain (for example `app.youragency.com`) and save. Open Accounts and click Open on one account. It should open on your domain, not on the platform's default address.
3. **Contact and conversation links.** Click Open on a contact in Speed to lead or Appointments, and on a conversation in Inbox. Each should land on the right record on your domain. If one opens a "not found" page, tell me which one: the link pattern is unverified.
4. **Install pages.** Open `https://subsync.kdsquares.com/installed` and `https://subsync.kdsquares.com/installed/error`. The wording should say "company", with no platform name.
5. **Shared page.** Run an audit on a real account, create its Share link and open it in a private window. No platform name and none of the banned words.

## Follow-up the same day: the three open items, resolved

King asked why the three open items could not simply be built or settled. Result:

1. **Install link host (settled by the platform's own documentation).** The platform's help article "OAuth consent for marketplace apps" says "For branded installs, use https://marketplace.leadconnectorhq.com/oauth/chooselocation", and that the same consent page runs on that host. `/api/oauth/install` now sends people there by default (`BRANDED_INSTALL_HOST` in `src/lib/ghl/scopes.ts`); the standard host is only used if asked for. The platform's white-label rules for marketplace apps allow neutral names such as "your CRM" or "LeadConnector" on that screen. Test: `scopes.test.ts`. Not done: clicking through a real install on the new host (it grants access to an account, so King does it; see check 6).
2. **Link patterns (checked on King's live CRM).** On the white-label domain `app.kdsquares.com` (captured by the real sign-in and stored for the test account, so the capture itself is verified), the CRM's own menu links are `/v2/location/<id>/dashboard`, `/conversations/conversations`, `/contacts/smart_list/All` and `/opportunities/list`. Our dashboard, conversations and opportunities links match them exactly. The two links to a single record (`/contacts/detail/<id>` and `/conversations/conversations/<id>`) could not be proven: the embedded browser would not render any CRM list or record page (even the stock Contacts list stayed blank), so the page content was not seen. The contact detail pattern is corroborated by a community post and the CRM accepted the address without redirecting. Still a King check (check 3).
3. **Product name (built).** When a company sets its business name in Settings, the product name is replaced by it on every screen: page text, the browser tab title, hover and placeholder text, and messages that come from the server (`src/app/app/brand-text.ts`, attached in `dashboard.tsx`). The demo sign-in now carries its brand too. The Slack digest headings no longer name the product. Browser test: with the name "Acme Marketing", 8 screens show no "SubSync" anywhere and show the company name. Not covered: the page before sign-in finishes ("Loading SubSync" for a moment), the public pages, the shared audit page, and email sender addresses.
