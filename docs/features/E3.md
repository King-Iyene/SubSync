# E3: Slack alerts

Status: reviewed and documented (31 Oct 2026). Recommendation: **KEEP**. It is the smallest integration (one scope) and works for other companies without a marketplace review.

## Distribution rules for other workspaces (CHECK, answered from Slack's documentation and a developer guide that cites it)

A new Slack app can only be installed in its own workspace until the developer presses **Activate Public Distribution** under Manage Distribution after the checklist is green (an HTTPS redirect address and similar). That step needs no Slack Marketplace review and takes effect at once; the Marketplace is optional but recommended for commercial distribution, and a workspace admin can still restrict installs to Marketplace apps. **King's step:** press Activate Public Distribution once (listed in `docs/CONNECTIONS_SETUP.md`, step 6).

## Scopes

Exactly one: `incoming-webhook`. SubSync can post to the one channel the person picks and nothing else: it cannot read messages, list channels or see people. The address Slack returns is stored encrypted and is never shown again.

## Tested

Connect (Slack's own page, a signed return value tied to the installation; a forged return is refused with 400), a post to the chosen channel, only `hooks.slack.com` addresses accepted (a saved setting can never make the server call another address), disconnect, and removal on uninstall and "Delete my data". Message content uses the verified numbers and none of the banned words (the digest and alert text pass the banned-terms scan; headings no longer carry the product name). Slack's rate limit for incoming webhooks is about one message a second per channel; SubSync sends one message per run, so it is nowhere near it.

## Needs King

Create the Slack app and add the two keys to Vercel (steps in `docs/CONNECTIONS_SETUP.md`), then press Connect Slack once to see a real message arrive.

## King's 5 checks

1. Connect Slack from Connections and pick a channel: a "connected" message arrives.
2. In Settings press the Slack test button: a test message arrives.
3. Raise a test alert (or wait for one): it arrives once, with no duplicate on the next run.
4. The message has no platform name and uses plain words.
5. Disconnect: nothing more arrives.
