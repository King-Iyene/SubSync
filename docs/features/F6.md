# F6: Account audit and Share link (the sellable asset)

Status: built and verified (31 Oct 2026). Evidence at the bottom.

## Goal

The audit is correct, sales-ready, and the public link is safe.

## What the code did at the start of the stage (found by reading it)

1. The audit's numbers come from the same counted deals, appointment rules and speed rules as F1 to F3 (one definition each), with counted facts and estimates labelled apart. Nothing to rebuild there.
2. The share link: a 192-bit random token (good), noindex (good), no account names (good), but it lived for 30 days, could not be switched off, had no view count, no rate limit, no link-preview tags (so a chat app could preview whatever the page title said), a dark page that printed as white text on a white sheet, and no fix plan.

## Decisions

- **Token:** unchanged, 24 random bytes (192 bits), unguessable by design.
- **Expiry:** 14 days by default (was 30), shown on the page and in the app.
- **Switch off:** the owner can revoke any of their links from the audit screen; only the owning installation can (another company, a client's own staff and a made-up id all fail), the action is written to the audit log, and a switched-off link shows nothing.
- **View count:** each open of a valid link adds one view and a last-opened time, shown in "Your share links".
- **Rate limit:** 30 lookups a minute per address on the public page, refused before the database is touched.
- **Previews:** the page sets generic title and description for link previews (no name), noindex, no archive, no snippet, and no referrer.
- **Snapshot date and expiry** are on the page; the fix plan ("What we found" then "One-page fix plan", five steps with what to do) is on the public page and printed with the in-app audit.
- **Print:** the public page prints with a white background and dark text on A4 and Letter, the sign-up button is not printed, and an item is never split over two pages.
- **Demo:** the demo installation holds the public sample audit, so its links are never listed or switched off from the demo.

## Acceptance criteria

1. Link security tests pass (expiry, view count, revoke by owner only, no names, noindex, previews, rate limit).
2. The public page is checked logged out and cannot reach any other data.
3. The print layout is checked on A4 and Letter.
4. `npm run verify` green.

### A bug the tests found

The public page read the clock before touching the database, which this project's rendering mode treats as an error ("blocking prerender current time"). The page worked, but it made the dev server unstable and the tenancy run failed with "fetch failed". Fixed with `connection()` before the clock read. Separately, my first rate-limit check built the link from `NEXT_PUBLIC_APP_URL` (localhost:3000 on this machine), not the test server.

### Self-review (S0 blocks release, S1 fix before pilot, S2 fix soon, S3 note)

- **S1: the rate limit is per server instance.** On Vercel two requests can reach two instances, so the real limit is looser than 30 a minute. The 192-bit token is what makes guessing impossible; the limit only makes it cheaper to refuse.
- **S2: the view count counts every open of the link, including your own and any chat-app preview robot that does not respect noindex.** It is a count of opens, not of people.
- **S2: a page cannot be proven to be absent from a search engine,** only that it asks not to be there (noindex, noarchive, nosnippet).
- **S3: PDFs were generated by the browser's print engine; a human should look at one printed copy** (check 4 below).
- No S0 findings.

### King's 5 checks

1. Open Account audit on KD Squares Test (or the all-accounts view) and press **Share link**. It says the link works for 14 days.
2. Open the link in a private window: no account or client names, the snapshot date and expiry date are shown, and there is a "What we found" list and a "One-page fix plan".
3. Paste the link into a chat app (WhatsApp, Slack): the preview says only "Account audit", with no names.
4. Print the shared page (or save as PDF) on A4 and on Letter: it should be light, readable and fit on one or two pages.
5. Back in the audit, under "Your share links", press **Switch off**. Reload the private window: the link shows nothing. The list shows it as switched off and how many times it was opened.
