## 2. The five evaluation lines (principle 1)

- **(a) Decision and for whom.** King and every pilot agency decide whether SubSync is safe to install on other businesses' customer data; a client's own staff must be able to trust that they see only their account; the agency owner decides when to delete everything.
- **(b) Data truly available.** Nothing new is read from the platform. Everything here is our own database and code, tested against the real database (`tests/unit/data-inventory.test.ts` compares the inventory with the live schema, 39 tables) and against two real fixture companies over HTTP. The install event's `whitelabelDetails.domain` is documented but a real signed install event was not available tonight: it is covered by a parser test and a database test, and the capture on sign-in already ran on King's real agency (stored `app.kdsquares.com`). NOT VERIFIED LIVE: a real install event carrying the domain.
- **(c) Does the CRM already do it.** No. Nothing here duplicates a CRM feature.
- **(d) Simplest version that proves value.** Remove, do not hide: the cross-client card and the "save it in an account" setting are deleted, not flagged. The inventory is one file next to the schema, with the old hand-written lists replaced by output of it.
- **(e) Risk.** Data and privacy: the whole stage is risk reduction. Scope: none added. Cost: none. Live-database risk: two additive changes applied with backups (below). Behaviour change for the real installs on merge: the Meeting notes page disappears (King's decision) and "Delete my data" needs the owner's sign-in.

## 3. What was built

- **N48 removed.** The Leads card, its query (`overlap`), the Duplicates tile "Same person, other clients" and its sentence, and the `crossAccount` count are gone, and so is the debug count in `scripts/audit-real.ts`. Nothing compares people across client accounts any more: no agency-only variant remains, so there is nothing to disclose. (A contact search over all of an agency's own accounts is search, not matching, and stays.)
- **N93 removed.** The select and its handler, `PUT connections/:id`, `setDefaultAccount`, the `defaultLocationId` fields and the fallback in routing are gone; the column `connections.default_location_id` stays unread and unwritten. A meeting nobody can be matched to is counted, never saved, for every connection, including a single business's (before, a business's unmatched meetings were saved in its own account; they are now only counted, to match the migrated "do not save it" value).
- **Matching tightened to "certain only"** (spec 7, principle 13, the same risk as N48): an email that two records have (two clients, or two records in one account) decides nothing, and a meeting whose matches sit in two different clients is not saved. Names and phone numbers never match. Attendee emails are compared in lower case (a mixed-case address used to miss its contact; found by the new database test).
- **N83.** `src/lib/data-inventory.ts` (every table, every personal column with a plain label, secrets, "never stored" promises, nouns for deletion). The Settings card "What we store", the privacy page's list and its deletion paragraphs, and the help answer about removing data are produced from it. "Delete my data" is for the agency owner (or a business's own administrator): `mayDeleteData` decides at sign-in, the signed session carries `dataOwner`, `POST settings/purge` refuses anyone else (and writes `data.purge_refused`), needs the typed word, and writes `data.purged`. The button is disabled with a plain reason for everyone else. Share link days now come from one constant (`SHARE_LINK_DAYS`).
- **N84.** The unit test over every router route plus the HTTP test over two real companies. Found and fixed: a client's Getting started reported whether the agency had set up Slack and an email address (it now drops those steps).
- **N82.** The login domain is now found at sign-in and in the install event, stored per company (`settings.detected_app_domain`, new column), and Settings shows "Open links go to X, found automatically" with a field that is only an override and a button to take the override off. Bug fixed: every save of the Settings form used to freeze the found address as "typed by hand" (the form sent it on every save). The banned-terms scan now also reads quoted values inside database queries and the platform and sync code; it found "your agency" in two cron queries and "GHL request failed" / "this agency" in two error messages that are stored as sync errors and shown on screen; all four reworded, plus the demo company name.
- **Item 6.** Two switches in the existing flag system, both off by default (`DEFAULT_OFF`): `zoom_meet` (Zoom and Google Meet) and `meetings` (the Meeting notes page). With `zoom_meet` off: the Zoom card, stored Zoom connections, the Zoom sign-in start, the Getting started wording, the Meeting notes page wording and the privacy sentence all drop Zoom. The Zoom callback and notification routes keep answering. Slack and Fathom stay on Connections. With `meetings` off: no menu item, the page says "switched off", Getting started has no meeting step; the "Meeting notes privacy" switches (transcripts, notes to the CRM) stay visible while a meeting tool is connected, so a connected Fathom can always be switched off.
