# F4: Inbox & SLA

Status: built and verified (31 Oct 2026). Evidence at the bottom.

## Goal

Unanswered conversations are correct and clearly labeled.

## What the code did at the start of the stage (found by reading it)

1. Today and Overview counted waiting conversations over 30 days; the Inbox list split them at 7 days and its card said "last 7 days", so the same account read 24 on Today and 13 on Inbox. Nothing said why.
2. The Inbox list was cut at 300 conversations, so a large account could show a smaller number as if it were the total (the daily brief used the same cut).
3. No count by channel; the CSV had no channel column.
4. No rule written down for internal notes, automatic replies or deleted conversations.

## Decisions

- **One definition and one window** (`docs/METRICS.md`, "Waiting for a reply"): the customer wrote last, past the reply target, within 30 days. Every screen uses it. The Inbox headline says it in words and splits the same total into "newer than a week" and "older than a week" so the parts add up.
- **The rule is a pure function** (`waiting.ts`) and a database test proves the SQL and the function agree on every demo account.
- **Internal notes and system activity are never the customer waiting.**
- **Automatic replies:** treated as a reply. A setting to ignore them was not built, because the conversation list does not say who sent the last message; written down as a known limit.
- **Channels** are named in words and counted for the waiting conversations; the CSV has a Channel column.
- **The list limit is 2,000** (as the exports already used) and the screen says when it is hit.

## Edge cases (tests)

Exactly at the target is not yet over it; 29 and 31 days; a reply, an automatic reply, an internal note and a call we placed after the customer; no time, a broken time, a time slightly in the future; an unknown channel; five channels at once on the demo (text, email, WhatsApp, Facebook, Instagram); a conversation inside the target; a 40 day thread; the CSV against the headline.

## Acceptance criteria

1. Tests green. 2. The windows are consistent with Today (the Inbox total equals the Overview number). 3. Numbers match the database. 4. `npm run verify` green.
