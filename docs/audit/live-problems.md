## 1. Dialer save error ("Could not save the dialer choice. Try again.")
Flow: `DialerSetting` (src/app/app/ds/dial-button.tsx:64) -> `useDialer.set` -> `api.put("people/dialer")` (line 29; ANY failure becomes that message, so the real cause is hidden)
-> router.ts:1804 `handlePeople` -> people-routes.ts:135-142 -> `setDialer` (src/lib/analytics/people-list-queries.ts:320).
It writes ONE row: table `saved_views` (page 'people-prefs', name 'dialer'), `insert ... on conflict (installation_id, owner, page, name)`.
- `saved_views` comes from `20261102060000_f4_saved_views.sql`, NOT from f10_people (that one only adds `contact_tag_events` + a GIN index). So the hypothesis is half right: a prod database missing the newest migrations (f4 is #32 of 39) would make this insert throw (no table, or no unique index for ON CONFLICT) -> 500 -> toast. NEEDS_KING.md:103 says f4 migration is applied "after merge" by the lead; unverified for prod.
- Caveat: `GET people/options` (people-routes.ts:61) also calls `getDialer` on the same table inside Promise.all, so if the table were missing the People page itself should fail to load. If People loads fine, suspect instead an error in the insert (unique index missing) or a 5xx/timeout on PUT. Check Vercel logs for PUT /api/app/people/dialer and `select to_regclass('public.saved_views')`, `\d saved_views`.
- Permission is NOT the cause: access.ts allows PUT people/dialer for agency (all), business (line 124) and client (line 115). Demo is not blocked either.
- Fix: apply the missing migrations to prod (all 13 after the last applied one, f4 first); also make the client show the server's error text/id instead of a blanket message (moot once the setting is removed).

## 2. Header filter block

Move industry/owner/test filters into that dropdown's footer or into Clients; move per-account freshness to Settings > Sync status (already there).
Files to change: src/app/app/ds/filters.tsx (FilterDrawer, AccountScope), src/app/app/views/sync-status.tsx (drop "Each account"), src/app/app/dashboard.tsx:414-421, src/lib/design/filters.ts (describeHidden text line 127).
